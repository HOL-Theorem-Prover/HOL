# Cryptographic curve instances

secp256k1, P-256, BN254 and BLS12-381 groups, generator orders, cardinalities,
cofactors, endomorphisms and twist embeddings. These are mathematical models,
not optimized implementations or pairing evaluators.

## Contents

* `secp256k1Instance`, `p256Instance`, `bn254G1Instance`,
  `bls12381G1Instance`: parameters, generators and exact generator orders.
* `cofactorOneInstances`: full cardinalities for secp256k1, P-256 and BN254 G1.
* `secp256k1Endomorphism`: the coordinate endomorphism and scalar eigenvalue.
* `bls12381Cardinality`: full BLS12-381 G1 cardinality and cofactor.
* `pairingTwistInstances`, `pairingTwistMorphisms`: G2 generators and
  embeddings into degree-twelve curve groups.
* `bn254TwistCardinality`, `bls12381TwistCardinalityCertificates`,
  `bls12381TwistCardinality`: full G2 cardinalities and supporting certificates.

## Interfaces

`*_group` contains all rational points; `*_subgroup` is generated by the
standard point. Cofactors are full curve cofactors, not hash-to-curve cofactors.
Fields come from [field_certificates](../../field_certificates/README.md);
[certificate automation](certificates/README.md) belongs to this instance package.
Neither generic curves nor field infrastructure depends on it.

For BLS12-381 G1 and both G2 twists, the standard generator spans a proper
subgroup. Exact generator order alone is not a full curve-cardinality proof.

## Build

With Poly/ML and a CV-capable standard or experimental kernel, run here:

```sh
"$HOLDIR/bin/Holmake" secp256k1InstanceTheory.uo
```

Omit the target to build all instances, including expensive cardinality proofs.
The full package runs at selftest level 3; certificate regressions run separately
at level 1.
